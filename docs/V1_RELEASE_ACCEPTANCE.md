## Valid non-AUTO opportunities

A legitimate raw G3 `REVIEW` or `BLOCK` is policy behavior, not a development
failure. Record `ACCEPTANCE_OPPORTUNITY_RESULT=VALID_POLICY_NON_AUTO`, do not
override, regenerate, tune thresholds or prompts, and wait for the next natural
fresh mature cohort. Development remains closed and code remains frozen.

## External operational failures

Provider HTTP 5xx, rate limits, timeouts, temporary network/proxy failures and
temporary GitHub or YouTube outages are operational incidents when Remote Pay
Guide fails closed. Record
`ACCEPTANCE_OPPORTUNITY_RESULT=EXTERNAL_OPERATIONAL_FAILURE`; do not reopen
development or make speculative source changes.

## True release blockers

V1 source development may reopen only when all of these are true:

1. The failure is reproducible.
2. It originates in Remote Pay Guide source or a deterministic canonical contract.
3. A fix is required by the already-defined V1 contract.
4. The fix introduces no new V1 feature.

Examples include duplicate external writes, incorrect authorization or durable
identity, unsafe control restoration, corrupt state transitions, duplicated
canonical provider calls, unexpected policy override, wrong account/platform
binding, task corruption, duplicate publishing, data corruption or a security
failure. Any change must be labeled `V1_RELEASE_BLOCKER_FIX`.

## Non-blockers and V1.1 backlog

The following do not reopen V1: external provider failures, normal OAuth token
refresh, valid policy outcomes, absence of an AUTO candidate in one cohort,
unconfigured optional platforms/providers, future creative or business-signal
optimization, and dashboard/operator UX work.

G4-C real AI-video provider E2E, Instagram/Facebook live publishing, Meta setup,
multi-platform G6 proof, richer AI failover/account pools, prompt and novelty
tuning, analytics expansion, dashboards, operator UX and Postiz improvements
are V1.1 backlog. The real 72-hour autonomous soak is
`OPERATIONS_POST_RELEASE`, not a V1 closure requirement.
